# Notes about the development process for ´Keyrus Dataset Analyzer´

1. Understand the problem and break it down to its basic parts.
2. Create a GitHub repository for the project.
3. Create a project-description.md file with a comprehensive explanation of the problem, requirements and expected outcome.
4. Connect Vibe CLI and Claude to the repository via MCP.
5. Create a skill for Mistral vibe using Claude to generate a Development process based on the project-description.md, and using OMIMO's NUPP and p1.express project management methodology.
`Why Mistral? Tokenomics... because Claude's tokens are much more expensive, so I rely on smaller and cheaper models for easier tasks, and Claude for code intesive ones.´
6. Create a skill for Claude to follow the Development process generated by Mistral, using the project-description file as context.
7. Start the development using Claude in VS Code.

## Issues encountered

- **File-size limit contradiction.** `development-process.md` stated a 50MB upload limit in three places (Milestone 2.1's done-when, the File Parser Checklist, and the Deferred/backend rationale), while the Open Questions section resolved it at 15MB. The orchestration skill's reconciliation step caught this and flagged it rather than silently picking one — required a decision from me on which number was authoritative (15MB, since it was the resolved answer) before fixes were applied.
- **API-key delivery contradiction, self-inflicted.** I edited the Open Questions "API key setup" answer mid-session (UI-entered keys → `.env`-only, since the no-backend policy rules out a UI path for secrets), but Milestone 4.1's task text still said "via environment variable **or UI input**." The skill's reconciliation caught the mismatch on the next read and it was fixed to `.env`-only, plus a `.env.example` task was added since keys can no longer be entered through the app.
- **Dual-LLM-provider routing left ambiguous.** The Open Questions resolve on two providers (DeepSeek for data-analysis calls, Google AI Studio for report-text generation) but never say which specific feature (data dictionary / business insights / client questions) uses which. The roadmap now carries a best-guess routing (DeepSeek for 4.2/4.3, Google AI Studio for 4.4), explicitly marked as an assumption — **still needs my confirmation before Phase 4 is dispatched.**
- **No headless-browser tooling on this Windows dev machine.** Neither `chromium-cli` nor Playwright was available to screenshot/click-through the app after Phase 1, so verification fell back to lint/type-check/build passing plus a manual code trace of each done-when condition. I ran `npm run dev` myself and confirmed the upload flow worked end to end.
